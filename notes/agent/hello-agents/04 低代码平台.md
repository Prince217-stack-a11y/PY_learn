# 04 低代码平台

> **教材**：第 5 章《基于低代码平台的智能体搭建》
> **源码**：`code/chapter5/`（本章无需安装，四个平台为云端/自部署）
> **一句话**：低代码平台把"API 调用、状态管理、并发控制"封装成"节点/模块"，让你把重心从**实现细节**移到**业务逻辑**——本章实操 Coze、Dify、FastGPT、n8n 四个代表性平台。

---

## 4.1 平台化构建的兴起（第 5.1 节）

### 4.1.1 为何需要低代码平台

承接第 4 章纯 Python 实现的 ReAct / Plan-and-Solve / Reflection，本章是"从**手写代码**向**平台化开发**的重要转变"。低代码平台的**四大核心价值**：

1. **降低技术门槛**：把 API 调用、状态管理、并发控制封装为"节点/模块"，非专业开发者也能搭建。
2. **提升开发效率**：数小时甚至数分钟即可完成原本需要数天编码的原型。
3. **提供更优的可视化与可观测性**：端到端看到数据在节点间流动，哪一环耗时最长、哪个工具调用失败一目了然。
4. **标准化与最佳实践沉淀**：预设 ReAct 模板、优化过的知识库检索引擎、标准化的工具接入规范。

> 一句话：**"低代码平台并非要取代代码，而是提供了一种更高层次的抽象。"**

### 4.1.2 低代码平台的选择

| 平台 | 定位 | 最高光 | 最致命短板 | 适合谁 |
|---|---|---|---|---|
| **Coze**（字节） | 零代码/低代码 Agent 构建 | 插件库丰富、一键发布到抖音/飞书/公众号 | **不支持 MCP** | 快速原型、非技术用户 |
| **Dify** | 开源 LLM 应用开发与运营平台 | 模型中立、支持 MCP、可本地部署 | 学习曲线陡、高并发性能一般、API 不兼容 OpenAI | 企业级应用、复杂业务逻辑 |
| **FastGPT** | 基于 LLM 的知识库问答平台 | 知识库问答"第一等公民" | 模板生态薄弱、免费额度紧张 | 私有知识库问答、智能客服 |
| **n8n** | 开源工作流自动化工具 | "连接"能力极强（数百节点） | 内置存储非持久（重启即丢） | 深度业务集成、通用自动化 |

## 4.2 平台一：Coze（第 5.2 节）

### 4.2.1 功能模块

- **项目空间**：智能体仓库。
- **资源库**：工作流 / 知识库 / 卡片 / 提示词库。
- **空间配置**。
- **创建入口**：分"智能体"与"应用"。智能体又分**单智能体自主规划模式**、**单智能体对话流模式**、**多智能体模式**；AI 应用可做桌面网页端、小程序、H5 端。

**作者的"游戏比喻"（很好记）**：

| 功能 | 游戏里的对应 |
|---|---|
| 工作流 | 关卡通关路线图 |
| 对话流 | NPC 对话通关 |
| 插件 | 角色技能卡 |
| 知识库 | 游戏百科全书 |
| 卡片 | 快捷道具栏 |
| 提示词 | 角色的移动键 |
| 数据库 | 云存档 |
| 发布管理 | 关卡审核员 |
| 模型管理 | 游戏角色库（捏脸系统） |
| 效果评测 | 闯关评分系统 |

> **"模型决定了智能体的下限，但是扣子资源库给了你智能体的能力的无穷上限。"**

### 4.2.2 案例：构建"每日 AI 简报"助手

**步骤一：创建工作流**——资源库 → `+资源` → 工作流。

**步骤二：添加并配置信息源插件**，并"编排连接"为大模型模块的数据输入节点：
- **RSS**：`https://www.36kr.com/feed`（36氪）、`https://rss.huxiu.com/`（虎嗅）、`http://www.ithome.com/rss/`（it之家）、`https://feed.infoq.com/ai-ml-data-eng/`（InfoQ）。
- **GitHub 插件**：`q: AI`、`per_page: 10`、`sort: updated`。
- **arXiv 插件**：`count: 5`、`search_query: AI`、`sort_by: 2`。

**步骤三：设定角色（资深科技媒体编辑）与系统/用户提示词**（用变量注入数据源、并约束输出量）：

```
- **信息提取与整合：** 从输入源 {{articles}}、{{articles1}}、{{articles2}} 和 {{articles3}} 中，
  筛选并提取关于 AI、大模型、AIGC、LLM 等相关主题的文章标题及其对应链接…
- **学术论文摘要：** 从输入源 {{arxiv}} 中，根据字段 arxiv_title 和 arxiv_link…
- **开源项目筛选：** 从输入源 {{GitHub}} 中，筛选出最受瞩目且具影响力的 5 个 AI 开源项目…
```

输出要求：**10 条 AI 技术新闻、5 篇 AI 学术论文、5 个 AI 开源项目**。

**步骤四：测试、调试与多渠道发布。**

### 4.2.3 Coze 的优势与局限性

- ✅ 零代码体验、插件生态丰富、多渠道发布便捷。
- ⚠️ **不支持 MCP**（"我觉得这是最致命的"）。
- ⚠️ 部分插件需 API Key 与高级参数，复杂工作流"不仅仅是零基础就可以掌握的，需要一定的 JS 或者 Python 的基础"。
- ⚠️ 无法像 Dify/n8n 那样导入导出 JSON 编排（付费版导出为 zip，只能 Coze 内导出再导入；取巧做法是编排界面 `Ctrl+A`/`Ctrl+C` 复制再粘贴）。
- 💡 "模型是都可以接入的，提示词、编排是可以复制的，但是**工具插件的有无、是否丰富**就直接决定了你的智能体能否做出更好的效果或者意想不到的强大功能。"

## 4.3 平台二：Dify（第 5.3 节）

### 4.3.1 介绍与生态

**开源**的 LLM 应用开发与运营平台，融合 **后端即服务（BaaS）** 与 **LLMOps**：
- **分层模块化架构**：数据层、开发层、编排层、基础层。
- **模型中立**：内置支持数百种开源/专有 LLM（GPT、Deepseek、Llama 等）以及**任何兼容 OpenAI API 的模型**。
- **两种部署**：本地部署（Docker Compose 一键启动）与云端 SaaS。
- **Marketplace**：模型、工具、智能体策略（Agent Strategies）、扩展、捆绑包——"已拥有超过 8677 个插件"（另处提到"9000+ 工具和 API 扩展"）。

### 4.3.2 案例：构建超级智能体个人助手

**第一步：创建插件与配置 MCP**——用魔搭社区 MCP 市场，选 **hosted** 类型，以高德 MCP 为例生成专属 MCP 配置 JSON。
> **推荐 SSE 模式**，因为"在 Dify 中使用 SSE 模式通信更加流畅稳定"。

**第二步：编排架构**——采用**多智能体 + 问题分类器进行智能路由**。功能模块：
- **日常问答**（兜底通用问答）
- **文案润色优化**
- **多模态内容生成**（图片、视频）
- **数据查询与可视化**
- **MCP 工具**（高德地图、饮食推荐、新闻资讯）

**提示词模板结构**（Agent 主提示词）：`Role: 日常问题咨询专家` → `Profile`（language / description / background / personality / expertise）→ `Skills` → `Rules` → `Workflows`（步骤 1-5）→ `Initialization`。
**文案优化模块**用"角色人设 / 背景 / 任务目标 / 限制提示 / 输出格式要求"五段式。

### 4.3.3 Dify 的优势与局限性

- ✅ 模型中立、插件生态庞大、支持 MCP、可私有化部署。
- ⚠️ 学习曲线较陡。
- ⚠️ **高并发下性能瓶颈**——"核心服务端组件由 Python 语言实现，与 C++、Golang、Rust 等语言相比，性能表现相对较差"。
- ⚠️ 多模态支持不足；企业版成本较高。
- ⚠️ **API 格式不兼容 OpenAI**。

## 4.4 平台三：FastGPT（第 5.4 节）

### 4.4.1 介绍与核心功能

**开源**的、基于 LLM 的知识库问答平台与 Agent 构建工具，定位"**企业级 AI 生产力引擎**"。
> **"与 Coze 的零代码体验和 Dify 的全栈开发能力不同，FastGPT 将知识库问答作为第一等公民。"**

围绕"**数据导入 → 智能分块 → 向量检索 → 对话生成**"深度优化。
- **工作台**：对话门户、工作台、知识库、账号。
- **Agent 类型**：工作流、对话 Agent、对话 Agent V2(Beta)。
- **知识库处理参数**：可选"分块存储"或"问答对提取"；分块条件如"原文长度 > 1000 字符时触发分块"；可开启**标题加入索引**、**自动生成补充索引**、**图片自动索引**。
- **免费版额度**：100 积分、600 条知识库索引、1 个团队成员、10 个 Agent、3 个知识库、30 天对话记录保留、30 QPM、单次可上传 5 个 50MB 文件。

### 4.4.2 案例：构建"智能投顾助手"

- 配置 MCP 工具：实时股票行情、金融数据与图表生成（如魔搭社区基于 TypeScript 的"可视化图表 MCP Server"、阿里云百炼官方 MCP）。
- 知识库构建 + MCP 接入 + 可视化工作流编排（意图识别、问卷收集、报告生成）。

### 4.4.3 优势与局限性

- ✅ 知识库问答深度优化；开源自部署；免费版够用。
- ⚠️ 模板生态相对薄弱；免费版额度紧张；社区与英文文档仍在完善。
- ⚠️ 寻找并配置 MCP 服务对非技术用户仍有门槛。

## 4.5 平台四：n8n（第 5.5 节）

### 4.5.1 节点与工作流

本质是**开源工作流自动化工具**，而非纯 LLM 平台。强项在"**连接**"——数百个预置节点，可把 SaaS 服务、数据库、API 与 LLM 节点串成自动化流程。学习曲线相对陡峭。

> **"在使用 n8n 构建智能应用时，我们实际上是在设计一个更宏大的自动化流程，而大语言模型只是这个流程中的一个（或多个）强大的'处理节点'。"**

**核心概念**：
- **Trigger Node（触发节点）**：**"一个工作流必须有且仅有一个触发节点。"**
- **Regular Node（常规节点）**。
- 数据在节点间以**结构化 JSON** 传递。

### 4.5.2 案例：搭建智能邮件助手

**第一步：准备 Agent 的"记忆"（私有知识库）**——三步：

```javascript
// ① Code 节点写 JSON 知识
return [
  {"doc_id": "work-schedule-001",
   "content": "我的工作时间是周一至周五，上午9点到下午5点。时区是澳大利亚东部标准时间（AEST）。"},
  ...
];
// ② Embeddings Google Gemini 节点向量化（模型 gemini-embedding-exp-03-07）
// ③ Simple Vector Store 节点（Operation Mode: Insert Documents，
//    Memory Key 相当于数据库"表名"，如 my-dailytime）→ 手动执行一次即加载入内存
```

**第二步：创建 Agent 主工作流**——以 `Gmail` 节点为触发器（Event = `Message Received`），用统一的 `AI Agent` 节点整合 LLM、Memory、Tools。整体决策逻辑：

```
接收（Gmail 触发） → AI Agent（思考 → 决策 → 工具调用） → 回复
```

### 4.5.3 优势与局限性

- ✅ 连接能力极强（数百节点）、开源、通用自动化。
- ⚠️ 复杂工作流出错时"需要逐个节点检查其输入输出来定位问题"。
- ⚠️ **内置存储非持久**——`Simple Memory`、`Simple Vector Store` 都基于内存，"n8n 服务一旦重启，所有对话历史和知识库都将丢失。**这对于生产环境的应用是致命的**"，需换 Redis、Pinecone 等外部持久化。
- ⚠️ 版本控制与多人协作不如传统代码（导出 JSON 管理，"远不如 `git diff` 代码来得清晰"）。
- ⚠️ 超高并发下节点调度有性能开销。

## 4.6 平台选型与"混合开发"思维（第 5.6 节）

| 需求 | 推荐 |
|---|---|
| 快速原型验证、非技术用户 | **Coze** |
| 企业级应用、复杂业务逻辑、多模态生成 | **Dify** |
| 基于私有知识库的问答系统、智能客服 | **FastGPT** |
| 深度业务集成、通用自动化流程 | **n8n** |

> **最佳实践（教材原话）**："用低代码平台快速验证想法，用代码实现精细化控制；用平台处理标准化流程，用代码处理特殊逻辑。这种'**混合开发**'的思维，才是智能体工程化的最佳实践。"

---

## 4.7 必须掌握 / 易踩的坑

- ✅ 低代码平台的四大价值。
- ✅ 四个平台各自的定位、强项与致命短板。
- ✅ Coze 的"游戏比喻"记忆法。
- ✅ Dify 的模型中立 + MCP(SSE) + 多 Agent 智能路由。
- ✅ FastGPT 的知识库处理参数（分块/问答对/索引）。
- ✅ n8n 的 Trigger Node + JSON 传递 + 知识库三步。
- ⚠️ Coze 不支持 MCP，且难以导入导出编排。
- ⚠️ Dify 的 API 不兼容 OpenAI；高并发性能受 Python 限制。
- ⚠️ n8n 内置存储重启即丢，生产必须换外部持久化。
- ⚠️ 平台不是替代代码，而是更高层次的抽象——复杂逻辑仍需代码。

## 4.8 一页速查（Q&A 自测）

1. 低代码平台的四大价值？→ 降门槛、提效率、可视化可观测、标准化沉淀。
2. Coze 最致命的短板？→ 不支持 MCP。
3. Dify 的 MCP 推荐什么通信模式？为什么？→ SSE，因为在 Dify 中更流畅稳定。
4. FastGPT 的差异化定位？→ 把知识库问答作为"第一等公民"。
5. n8n 的本质是什么？→ 开源工作流自动化工具（LLM 只是其中一个节点）。
6. n8n 的 Trigger Node 规则？→ 一个工作流必须有且仅有一个触发节点。
7. n8n 内置存储的最大风险？→ 重启后对话历史与知识库全部丢失。
8. 低代码与代码的最佳关系？→ 混合开发：平台做标准化与快速验证，代码做精细化与特殊逻辑。
