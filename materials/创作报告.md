# 二面考核创作报告
## 一、整体思路：首先进行创作报告的写作把整体的开发流程思路确定下来 -> 然后进行代码文件的编写在这过程中与AI进行交互和做开发 -> 然后进行 PPT制作和文件测试最后拍摄讲解视频 

## 二、产品名称：伴学教练（coach.py） 
### 1、大致功能与流程:我告诉它要练哪个模块，它出题；我把答案写进文件；它读我的文件、跑检查、用大模型批改（有没有错、哪里能改）；结果记进错题本，下次优先安排复习。
### 2、用户流程：我告诉 Agent 要学习/练习哪个模块->Agent 给出该模块的练习题->我把答案写进它指定的文件（写代码）->Agent 读取我写的文件->Agent 判断：代码有没有错、有没有可以改进的地方->Agent 把结果返回给我，我查看->智能体记录学习情况作为储备

## 三、大致架构：

### 3.1 初版

| 层 | 职责                          | 用了什么技术 |
| --- |-----------------------------| --- |
| 交互层 | 终端对话 + 人机文件交接（用户写答案的文件）     | Python `input/print`、文件读写 |
| 业务层 | Agent 循环、出题、批改作业、llm调用、工具执行 | Python 3.13 + openai 库（OpenAI 兼容接口） |
| 数据层 | 错题本 JSON；题目 / 答案 / 报告文件     | 文件系统（UTF-8） | 

### 3.2 修订版

| 层 | 职责 | 用了什么技术                     | 层间协议 |
| --- | --- |----------------------------| --- |
| 交互层 | 终端对话 + 人机文件交接（用户写答案的文件） | Python `input/print`、文件读写  | stdin/stdout；文件 |
| 业务层 | Agent 循环、出题、批改作业、LLM 调用、工具执行 | Python 解释器 + openai 库 | 工具调用 JSON（tool_calls / tool 结果回传）；HTTPS（调用 OpenAI 兼容接口） |
| 数据层 | 作业文件（homework.py）；错题本（notebook.json）；学习报告（report_日期.md） | 文件系统（UTF-8）                | 文件 IO（JSON / Markdown / 文本） |
- （经过对于ai的询问，发现读作业文件时拿到的字符串 s 如果是空的，对它取下标（比如 s[0]）会抛 IndexError，所以在 read_homework 里先判断一下内容是不是空的）
- （在问过关于流程和协议的区分后我了解到协议的特点是：固定字段、固定类型、配对规则；其中https协议我熟悉，但是对于JSON工具调用为什么会算作协议，一开始不明白）
- （最后业务层与数据层交互使用的协议，经过讲解之后我觉得更像是对于数据存储格式的一种约束，用json的话更适合机器以及保存去阅读用md是为了方便人阅读，本质是对数据存储的协议）
## 四、核心功能：
- ### 1:可以进行人机交互对于用户关于某一块知识进行特定输出相关题目 
- ### 2：而且可以对用户写出的作业进行批改帮助用户，在练习中学习并且可以帮助用户养成良好的代码书写习惯 
- ### 3：具有记忆功能可以记录用户写错的代码题目并且返回报告文件，以帮助进一步的学习和复习 

## 五、开发调试：
- ### 1.一开始关于 import openai 模块时由于没有提前下载好，所以运行时直接报错：ModuleNotFoundError: No module named 'openai'，后面先进行包的下载然后在ai的建议下加了 try/except 保障
- ### 2.想要移除env文件时再次运行主程序出现报错，原因：代码内读取路径找不到该文件，修改：提交时 .env 替换为 .env.example 占位文件，Key 由使用者自行配置
- ### 3.经过两次测试后发现在同一天里，进行两次对话最后一次会把前面的覆盖，因为对于report文件的命名只精确到了天，而且关于写入内容的函数他会进行覆盖，修改：content = "\n\n---\n\n" + content ，这样是最不影响其它地方的修改

## 六、AI 协作说明：
- ### 1、在编写主要agentloop循环时，建议我利用for循环而非教材while循环，是因为我忘记了while更适合不知道次数，而for是适合已知次数
- ### 2、具体代码部分在几个函数定义里面，我让其帮助我生成框架节省时间，然后我来填核心内容 
- ### 3、关于最后的主循环部分我先给AI说明我对于循环的初步逻辑让他对我进行评价然后给我一份示例，我按照自己的需求进行修改 

## 七、核心代码思路：我先进行代码架构思考，让ai帮助我修改并给出注意的点，确定后让其生成框架或者冗杂部分，我来填写核心内里

## 八、可以改进的地方：（1、4为我的想法其余为ai的建议）
- ### 1、交互层可加"命令枚举"（/next、/submit、/quit），把裸输入解析成命令再进业务层，边界更清晰
- ### 2、业务层返回值可改为结构化数据，渲染（打印）全部收归交互层，便于测试和将来换界面
- ### 3、错题本记录可加唯一 ID 和 schema_version 字段，写入改为"先写临时文件再替换"的原子写，防止中途崩溃损坏数据
- ### 4、学习报告文件名可加时间戳，避免同日多次练习互相覆盖
- ### 5、题目可定义"作业文件契约"（固定入口函数名），业务层自动加载运行测试用例，让批改从"模型读代码判断"升级为"可验证的自动检查"
